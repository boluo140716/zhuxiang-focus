# 一炷香：账号体系（注册/登录/数据隔离）设计文档

- 日期：2026-08-05
- 状态：已获用户口头批准（2026-08-05）
- 依据：用户需求「添加登录注册页面」+ grill-me/brainstorming 确认结论

## 1. 背景与目标

**一句话定位**：从「单机单用户工具」升级为「人人注册登录、数据各管各的」的专注训练产品，为将来网页版 / exe / apk 三种形态共用同一套账号体系打地基。

**目标优先级（用户确认）**：
1. 完全开放注册，人人可注册登录
2. 数据彻底隔离：每个用户只看到自己的会话、分心、设置、印章
3. 无全局管理员，每个用户是自己数据的管理员
4. 第一个注册账号自动继承现有全部历史数据（无主数据）
5. 密码安全哈希存储、无硬编码密钥（将来开源 GitHub）
6. 登录状态保持（通行证 7 天有效，记住我）

## 2. 需求确认记录（brainstorming 结论）

| 问题 | 结论 |

## 3. 功能设计

### 3.1 注册
- 表单：用户名（唯一，登录用）、昵称（展示用）、密码
- 用户名重复 → 明确报错「用户名已被使用」
- 密码规则：最少 6 位（本地产品不做复杂强度要求，但留校验入口）
- 注册成功后自动登录（直接进入应用），无需二次登录

### 3.2 登录
- 用户名 + 密码
- 错误统一提示「用户名或密码不正确」（不泄露是哪个错了）
- 登录成功 → 发 JWT（有效期 7 天）→ 前端存 localStorage → 进入应用

### 3.3 数据继承（仅首次部署时触发一次）
- 注册时若数据库中**没有任何用户** → 该账号自动成为「数据继承者」：所有 `user_id IS NULL` 的历史会话/分心/设置全部归属该账号
- 已有用户后再注册 → 普通账号，从零开始

### 3.4 数据隔离
- 所有数据表按 `user_id` 隔离：session、distraction、setting
- 所有查询/写入强制带当前用户过滤（服务端依赖注入，前端无法绕过）
- 「唯一进行中会话」约束从全局改为按用户：每人同时最多一场 running 会话，跨用户互不影响（A 开始专注不会结束 B 的会话）
- 统计（daily/weekly/insights/next_target）、设置（黑名单/目标时长/深度时段/裸专注日）均按当前用户
- 印章、集印条、结业卷轴进度同理

### 3.5 登出
- 品牌栏新增「登出」按钮 → 清除本地 token → 回到登录页

## 4. 技术设计

### 4.1 数据模型
- 新表 `user`：id、username（唯一索引）、nickname、password_hash、created_at
- `session`、`distraction`、`setting` 各加 `user_id` 列（可空，用于继承迁移）
- 迁移策略（沿用现有 `_migrate()` 模式，幂等）：
  1. 建 user 表
  2. 给三张旧表加 `user_id` 列（若不存在）
  3. 旧数据不动（留 `user_id IS NULL`，等待首个注册者继承）

### 4.2 认证实现
- 密码哈希：`hashlib.pbkdf2_hmac`（sha256，随机盐 16 字节，迭代 ≥ 200_000），存 `盐$哈希` 单字符串，零第三方依赖
- JWT：标准库 `hmac` + `hashlib` 自实现 HS256（不引入 PyJWT 依赖，代码 ~40 行，单测覆盖）
  - payload：`{uid, exp}`，密钥首次启动随机生成（`secrets.token_hex(32)`）存 `data/auth_secret.key`（chmod 思路：仅本机可读；不入库、不进 git）
  - 密钥文件不存在时自动生成；存在则读取（重启不失效，token 不失效）
- FastAPI 依赖：`get_current_user`（读 Authorization: Bearer <token> → 验签 → 取用户），所有业务路由挂载

### 4.3 API
- `POST /api/auth/register`：{username, nickname, password} → 创建用户（首个用户触发数据继承）→ 返回 {token, user}
- `POST /api/auth/login`：{username, password} → {token, user}
- `GET /api/auth/me`：当前用户信息（前端启动时校验 token 有效性）
- 现有路由全部加用户过滤：sessions / distractions / stats / settings
- `/api/monitor/status`、`/api/monitor/hit`：保持公开（仅监控诊断信息，无用户数据；前端登录后才轮询）

### 4.4 桌面监控适配
- 监控线程上报分心时，取「最新开始的 running 会话」的归属用户，向该会话 POST 分心
- 边界（README 注明）：一台电脑同时只有一个人在用；多用户同时 running 时只记最新会话，属可接受取舍

## 5. 前端设计

### 5.1 登录/注册页视觉（延续书道道场）
- 沿用「一炷香」品牌语言：朱砂印章、衬线大字、宣纸/墨色双模式（昼/夜与主应用一致）
- 登录页 signature 元素：居中大香字印章 + 「焚香入定」式短文案，注册/登录两种状态切换时印章文案随之变化（登录=「入定」、注册=「开卷」），呼应产品「专注如修行」的世界观
- 表单用现有 `.panel` / `.btn-primary` 组件体系，不引入新设计语言
- 校验错误用现有 toast + 行内提示

### 5.2 会话与令牌
- token 存 `localStorage`（key：`yizhuxiang-token`）
- 离线暂存队列、本地离线会话均跟随当前登录用户；登出时清空本地会话与队列，避免串数据
- `apiDirect`/`apiWriteQueue` 统一加 `Authorization: Bearer <token>` 头
- 收到 401 → 清 token → 切到登录视图 + toast「登录已过期，请重新登录」
- 启动时：有 token → `GET /api/auth/me` 校验 → 通过进应用，失败跳登录；无 token → 直接登录页
- 登出：清 token + 回登录页

### 5.3 视图结构
- 新增 `#view-auth`（登录/注册双态，顶部品牌行保留）
- 已登录：三页导航（专注/统计/设置）+ 品牌栏「登出」
- 未登录：只显示登录/注册视图，其他视图不可达

## 6. 迁移与数据安全
- `data/focus.db` 现有数据不动，首次注册自动继承
- 密钥文件 `data/auth_secret.key` 随数据目录一起备份（README 说明「备份 = 复制 data/ 目录」）
- 无任何硬编码密钥；gitignore 确保 `data/` 不入库

## 7. 测试计划
- pytest：
  - 注册成功/用户名重复 409/密码过短 400
  - 登录成功/密码错误 401/用户不存在 401（同文案）
  - 无 token / 假 token / 过期 token → 401
  - 数据隔离：用户 A 建会话，用户 B 的 daily/stats/current/settings 看不到
  - 首账号继承：先有孤儿数据 → 注册第一人 → 数据归它；第二人注册不继承
  - JWT 签名验证（篡改 payload 被拒）
  - 迁移幂等（已有 user_id 列不重复加）
- jsdom：登录页渲染、注册流程、401 跳登录、登出、token 持久化
- e2e：注册 → 登出 → 登录 → 完整使用流程

## 8. 边界与限制（README 同步）
- 单机局域网服务：多用户同时「前台专注」的监控上报只记最新会话
- 密码不找回（无邮件服务），忘记密码 = 由管理员（部署者）删库重建或手动改库
- token 7 天过期，过期需重新登录
- 局域网内开放注册即开放给同一网络的所有人（README 提示：公共网络慎用）

## 9. 不做（YAGNI）
- 邮箱/手机号注册、密码找回
- 刷新令牌/双令牌体系
- 全局管理员后台、用户管理界面
- 云端同步（本轮只做同一台机器上的多用户；多端同步是后续版本）
- 第三方登录（微信/GitHub OAuth）
