# 待办页分区设计（2026-08-07）

- 状态：已获用户口头批准（2026-08-07）
- 依据：brainstorming/grill-me 结论（两个固定分区、各一个添加框、去掉类型切换按钮、每日任务也可专注）

## 1. 背景与目标

待办页目前是一个混合列表（普通待办 + 打卡项目，今日已完成的在底部「今日打卡」分组）。目标是把待办页改成两个固定分区，心智更清晰：

- **每日任务**：每天重复、可打卡，也可开始专心；完成不消失
- **普通待办**：一次性，只能通过开始专心完成，完成即消失

## 2. 页面结构

```
待办页
├─ 专注时长（共用，现有设置）
├─ 每日任务
│   ├─ 添加框（placeholder：每天想坚持的事）
│   ├─ 每日任务列表（含今日已完成，标「✓ 今日已完成」+ 连续打卡天数）
│   └─ 空状态：还没有每日任务，先加一件想每天坚持的事
└─ 普通待办
    ├─ 添加框（placeholder：接下来想专心的一次性事项）
    ├─ 普通待办列表（完成即消失）
    └─ 空状态：还没有普通待办
```

- 每个每日任务项：开始专心 / 完成打卡（仅未完成时）/ 改 / 删
- 每个普通待办项：开始专心 / 改 / 删
- **去掉**列表项上的「打卡」类型切换按钮；类型由添加框决定

## 3. 数据与接口

- 复用现有 `is_daily` 字段（True=每日任务）
- `POST /api/todos` 增加可选 `is_daily` 参数（默认 False）
- `PATCH /api/todos/{id}` 保留现有能力（含 is_daily），前端不再调用切换
- 每日任务完成规则不变：手动「完成打卡」或从待办开始专心正常完成均联动打卡；次日自动重置为未完成，连续天数保留
- 普通待办完成规则不变：从待办开始专心正常完成 → 联动标记完成 → 消失

## 4. 技术实现（前端为主）

- `static/index.html`：待办页改为两个分区，各自独立添加框与列表容器；空状态文案分区
- `static/app.js`：
  - `renderTodos` 改为按 `is_daily` 分两区渲染（每日任务含已完成项，普通待办只含未完成项）
  - 新增两个添加函数（每日/普通），POST 时带 `is_daily`
  - `buildTodoItem` 移除「打卡」切换按钮；每日任务项保留「完成打卡」
  - 开始专心 / 时长设置 / 打卡联动逻辑不变
- `static/style.css`：分区标题、分区内列表样式（轻量）

## 5. 测试
