# 回神仪式自适应档位设计（2026-08-07）

- 状态：已获用户口头批准（2026-08-07，默认判据已确认）
- 依据：grill-me/brainstorming 结论「初期干预要多一点，之后按用户表现自动减少」+ 用户选择 C（温和反馈 + 轻选择结合）

## 1. 背景与目标

**现状**：回神仪式目前只有一张卡片（「分心很正常，回来就好」+「我回来了，继续」按钮），所有触发时机行为一致，不随用户表现变化。

**一句话目标**：把回神仪式从固定卡片变成随用户表现自动升降的三档干预——表现差时多帮一点（觉察），表现好时逐步退出（脱离产品）。

**硬约束**：全程不引入倒计时、输入框、惩罚（用户已明确拒绝）。

## 2. 需求确认记录（brainstorming 结论）

| 问题 | 结论 |
|---|---|
| 方向 | A：脚手架递减——初期干预多，按表现自动减少 |
| 回神仪式的加重形式 | C：温和反馈 + 轻选择结合 |
| 轻选择选项 | 有点累 / 有点烦 / 就是走神了（可跳过） |
| 判据默认值 | 10 分钟内再破功 = 连续破功；3 天无连续破功降 L2；7 天无破功降 L3 |
| 初始档位 | 新用户 / 数据不足默认 L1 |
| 档位可见性 | 展示当前阶段，不可手动改 |

## 3. 功能设计

### 3.1 三档强度

- **L1 受训期（默认初始档）**：破功卡片 = 温和反馈 + 轻选择 + 一句建议 + 「我回来了，继续」按钮
  - 温和反馈：「这是今天第 N 次回来，每一次都是练习」（N = 当天分心记录总条数）
  - 轻选择：有点累 / 有点烦 / 就是走神了（可跳过，跳过即视为「直接继续」）
  - 对应建议：有点累 →「去接杯水，再回来」；有点烦 →「先做最简单的 5 分钟」；就是走神了 →「好，直接继续」
- **L2 过渡期**：只留温和反馈一行 + 按钮（= 现状）
- **L3 预备毕业**：不弹仪式，破功后静默记录，页面安静继续

### 3.2 升降判据（每日结算，滚动近 7 天）

- 连续破功 = 同一天内两次破功时间差 ≤ 10 分钟
- 升回 L1：当天出现连续破功
- 降 L2：连续 3 天无连续破功
- 降 L3：连续 7 天无破功记录
- 降档逐级进行：仅当前 L2 且满足「连续 7 天无破功」才降 L3，不跳级
- 数据不足（无分心记录历史）→ L1
- 裸专注日当天：固定按 L3 处理（不弹仪式）

### 3.3 数据与计算

- 后端纯函数服务：输入近 7 天 Distraction 记录 → 输出档位（1/2/3）
- 档位存 Setting（key = ritual_stage，value = "1"/"2"/"3"），每日首次访问时惰性结算（无定时任务）
- 新会话创建时把 session.stage 同步写入当前档位（awareness=L1 / training=L2 / habit=L3），复用预留字段

### 3.4 接口与前端

- 新增 GET /api/settings/ritual-stage → { stage: 1|2|3 }，读取时惰性结算
- 前端启动时拉取档位；破功触发仪式时按档位渲染（L1 完整卡片 / L2 简化 / L3 不弹）
- 设置页展示「当前训练阶段」：受训期 / 过渡期 / 预备毕业，只展示不可手动改

## 4. 测试计划

- pytest：档位纯函数（连续破功判定、3 天降 L2、7 天降 L3、升档回退、数据不足默认 L1、裸专注日 L3）
- jsdom：L1 卡片完整渲染（反馈 + 选择 + 建议）、L2 简化、L3 不弹
