# 干预递减与毕业机制升级设计（2026-08-07）

- 状态：已获用户口头批准（2026-08-07，毕业阈值 60% / 50% 已确认）
- 依据：grill-me/brainstorming 结论（干预按表现递减、streak 放宽为激励、毕业单独验证）

## 1. 背景与目标

回神仪式档位（v36）验证了档位机制。本轮把「干预递减」扩展到全部干预手段，并升级连续达标与毕业机制：

- 干预强度按用户表现三档递减（L1 受训 / L2 过渡 / L3 预备毕业），不只回神仪式
- streak 放宽为纯激励信号：没使用产品不算断，用了但没达标才算断，不设休息上限
- 毕业不再依赖「连续达标 28 天」，改为「近 4 周达标率 + 靠自己比例」双条件

## 2. 干预递减（三档统一）

| 干预手段 | L1 受训期 | L2 过渡期 | L3 预备毕业 |
|---|---|---|---|
| 回神仪式 | 完整（反馈+选择+建议） | 简化（只反馈） | 不弹 |
| 黑名单自动检测 | 命中记分心 + 强卡片 + 每 2 分钟提醒 | 只记录，不弹卡片 | 不检测 |
| 无操作补问 | 回页面补问 | 不补问 | 关闭 |
| 手机拿起归因 | 弹窗归因 | 自动记默认原因，不弹 | 不感知不记录 |

- 裸专注日：全部干预关闭（保持现状）
- 实现要点：
  - L3：`/api/monitor/settings` 返回空 blacklist → 监控线程不检测黑名单
  - L2：监控照常上报记录，前端按档位不弹卡片 / 不弹窗 / 不补问
  - L1：全部维持现状

## 3. streak 新规则

- 往回数达标日：**无会话记录的天直接跳过**（不设上限，旅行 / 生病不断）；**有会话记录但未达标的天才停**
- 今天未达标时从昨天起算（保留现有宽容）
- streak 变乐观是预期内的——它只是激励信号，不是毕业凭证

## 4. 毕业新条件

- 近 28 个自然日：**达标率 ≥ 60%**（约 17 天达标）**且 靠自己完成比例 ≥ 50%**
- 靠自己比例 = 近 28 天完成场次中自评 reliance=self 的占比（数据已有）
- 结业卷轴改为滚动展示「近 4 周达标 X% · 靠自己 Y%」，不再用「连续达标 28 天」

## 5. 展示

- 首页「连续达标 N 天」卡片保留（语义放宽）
- 结业卷轴文案改为达标率 + 靠自己比例，进度条按两个条件的达成度渲染

## 6. 技术实现

### 后端
- `app/services/training.py`：
  - `compute_streak(qualified, sessions, today)` 增加 sessions 参数：跳过无记录天
  - 新增 `graduation_status(sessions, today)`：返回近 28 天达标率、靠自己比例、是否满足毕业
- `app/routers/stats.py` weekly：附带毕业状态（达标率 / self_rate / 是否可毕业）
- `app/routers/main.py` monitor/settings：按档位返回 blacklist（L3 置空）

### 前端
- `static/app.js`：
  - 黑名单 hit 轮询：L2/L3 不弹强卡片（L3 无 hit 数据）
  - 无操作补问：L2/L3 不弹 overlay-idle
  - 手机归因：L2 自动记默认原因不弹窗；L3 不感知
  - 结业卷轴：按新毕业数据渲染
- `static/index.html`：卷轴文案与进度元素

### 测试
- pytest：streak 新逻辑（跳过休息、用了未达标断、今天宽容）、毕业判定（达标率阈值、靠自己阈值）
- jsdom：L2/L3 黑名单卡片不弹、无操作不补问、归因不弹 / 自动记
- e2e：版本断言 + 视觉截图
