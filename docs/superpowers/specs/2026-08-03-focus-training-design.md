# 专注训练营（FocusDojo）设计文档

- 日期：2026-08-03
- 状态：已获用户口头批准（2026-08-03）

## 1. 背景与目标

**一句话定位**：不是约束工具，而是"觉察 → 训练 → 习惯"三段式成长产品，目标是让用户**毕业**——连续达标后能脱离产品也能专注。

**目标优先级**（用户确认）：
1. 先解决自己用（边用边改，最快验证）
2. 再考虑练手/作品集（架构保持干净、可展示）
3. **纯用爱发电，不考虑商业化**——没有留存压力，"让用户毕业离开"可以放心作为产品目标

**核心哲学**：训练而非依赖。产品是"专注力健身房"，最终形态是用户不再需要它。

## 2. 用户痛点（按严重程度）

1. **手机刷不停**（最常发生）：本来要干活，一拿起手机就停不下来。
2. **拖延启动**：知道该做什么，但就是拖着不开始。

## 3. 产品概念

### 3.1 三段式成长路径

- **觉察**：让用户"看见"自己的分心模式（什么时候刷、刷了多久），把无意识行为变成看得见的数字。
- **训练**：渐进式增强专注时长（像举铁），配合启动仪式对抗拖延启动。
- **习惯**：固定节奏 + 连续达标 + 周复盘，把专注固化为能力；达标后毕业，转入"月度体检"。
- **三阶段是渐进叠加，不是串行关卡**：觉察（统计/归因）、训练（渐进时长）、习惯（连续天数/周复盘）在 MVP 中并存运行，只有"毕业"是终局目标。

### 3.2 双端角色区分（关键设计决策）

- **电脑端 = 工作主设备**：只判"在岗"，不判"走神"。页面切换 ≠ 分心（用户可能在看文档、查资料）。有键盘鼠标活动 = 在岗不打扰；超过 3-5 分钟无操作才轻问一句。**技术边界**：浏览器切到后台时弹窗不可见，故"轻问一句"在 MVP 中降级为"回到页面时补问"。
- **手机端 = 分心重灾区**：专注时手机本就该放下，所以"拿起手机"就是信号。拿起/切走 → 自动记录"离开中" → 回来 3 秒归因。

### 3.3 感知机制（产品主动，不依赖打卡）

核心转变：**"用户打卡" → "产品自动感知 + 3 秒轻确认"**。
- 电脑端：后台小助手轮询前台窗口，命中黑名单自动记分心。
- 手机端：浏览器切后台/回前台自动感知；回来弹一键归因（刷手机/工作/喝水/上厕所），不点默认记"刷手机"，先记后改。
- 用户唯一必须做的主动动作：点"开始"（同时完成启动仪式与计时开始，正好治拖延）。

### 3.4 抖音检测能力分层（诚实边界）

| 端 | 能力 | 技术路径 |
|---|---|---|
| 电脑端·抖音客户端 | ✅ MVP 即可做 | Python 轮询 Windows 前台窗口，匹配进程/标题 |
| 电脑端·抖音网页 | ✅ MVP 即可做 | 窗口标题含 douyin 识别 |
| 手机端·识别具体 App | ❌ PWA 做不到 | 需原生安卓（使用情况访问 + 无障碍服务），后期路线 |
| 手机端·拿起归因 | ✅ MVP 即可做 | PWA visibilitychange |

**分心黑名单**：可配置（默认内置抖音客户端+网页），设置页可增删（微信、微博、B 站、网站域名等）。

### 3.5 针对竞品缺陷的对策（六张牌）

竞品（Forest/番茄ToDo/禅定空间等）的机制是"管住环境"而非"训练能力"，六个结构性缺陷及我们的对策：

| 竞品缺陷 | 我们的对策 |
|---|---|
| ① 外部归因，能力没内化 | **脚手架递减**：产品支持逐步撤走——自动检测提醒 → 只提醒不检测 → "裸专注日"（不用产品自己扛）；每场结束自评"这次靠产品还是靠自己" |
| ② 破罐破摔（断签放弃） | **不归零机制**：失败不清零只降级；当天提供"回弹任务"（哪怕 5 分钟），完成即算恢复 |
| ③ 强度恒定无成长 | **自适应渐进**：完成率 > 80% 才加时长，< 50% 自动降回；难度维度含时长、分心容忍度、裸专注频率 |
| ④ 奖励饱和挤掉内在动机 | **不做金币/树**：奖励 = 每周"成长报告"（进步可视化），反馈即奖赏 |
| ⑤ 度量坐满不是专注 | **质量自评**：每场结束 10 秒自评完成度 + 心流感；有效专注 = 时长 × 完成度 |
| ⑥ 不训练中断恢复 | **恢复力训练**：分心 → 归因 → 10 秒回神仪式 → 继续，完整走完记一次"恢复成功"；支持"我忍住了"正面记录 |

## 4. 功能设计

### 4.1 觉察
- 电脑端黑名单自动检测（抖音客户端 + 网页窗口）。
- 手机端起/归因（一键，3 秒）。
- 日/周统计：今天刷了多少、专注了多少、几点最容易破功。

### 4.2 训练
- **启动仪式**：开始前 30 秒，写下"这次要完成什么"。
- **渐进时长**：第一周每次 15 分钟起步，每周 +5 分钟（可调）。
- **分心计数**：手动"破功"按钮 + 自动检测双通道，只记录不惩罚。
- **质量自评**：每场结束 10 秒自评完成度（0-100%）+ 心流感（1-5）；有效专注 = 时长 × 完成度。
- **恢复力训练**：分心 → 归因 → 10 秒回神仪式 → 继续，完整走完记一次"恢复成功"。

### 4.3 习惯
- **深度时段**：设置固定时段（如每天 9-11 点），到点提醒。
- **达标日定义**：当日完成 ≥ 1 个达标会话（实际时长 ≥ 当日目标时长 × 80%，且质量自评完成度 ≥ 60）记为达标日；周达标 = 一周 ≥ 5 个达标日。
- **连续达标天数** + **不归零机制**：失败不清零只降级；当天未达标时主页出现"回弹任务"入口（完成哪怕 5 分钟即算恢复，对抗"破罐破摔"）。
- **周复盘**：本周数据 → 下周建议目标时长（自适应：完成率 > 80% 才加，< 50% 降回）。
- **毕业机制**：连续 4 周达标 **且** 最后 2 周"裸专注"占比 ≥ 50%（数据证明开始不需要产品，不是到点放人）；毕业 ≠ 消失，转入"月度体检"模式（每月测一次专注力，不干预日常）。

### 4.4 设置
- 黑名单管理、当前目标时长、训练阶段、深度时段、提醒开关。
- 阶段说明（MVP 简化）：训练阶段由"目标时长档位"体现，不设串行关卡；阶段字段保留供毕业机制使用。

## 5. 技术架构

### 5.1 技术栈
- 后端：FastAPI + SQLite（SQLModel 做数据模型，API 与模型共用类型）。
- 前端：单页 HTML + 原生 JS，做成 PWA（可安装手机桌面、可离线）。
- 桌面检测：Python 后台小助手，ctypes 调 Windows user32 轮询前台窗口。
- 启动：`python run.py` 一键拉起 Web 服务 + 检测助手。

### 5.3 数据模型

- `session`：id、task_name、planned_minutes、actual_minutes、started_at、ended_at、status（running/completed/abandoned）、device（phone/desktop）、stage（awareness/training/habit）、completion_score（0-100，结束自评）、flow_score（1-5，结束自评）。
- `distraction`：id、session_id（可空）、occurred_at、source（manual/auto_detect/phone_pickup）、app_name（抖音/微信/…）、resolved_reason（刷手机/工作/喝水/上厕所）、duration_minutes。
- `settings`：key-value（黑名单列表、当前目标时长、训练阶段、深度时段、提醒开关）。
- 约束：**全局同一时刻只允许一个 running session**（开始新会话时自动结束旧会话并标记 abandoned）；MVP 会话属于发起设备，不跨端合并。
- 统计不单独建表，由 session + distraction 实时聚合。

### 5.4 核心 API

- `POST /api/sessions`：开始专注。
- `PATCH /api/sessions/{id}`：结束/完成/放弃。
- `POST /api/sessions/{id}/distractions`：记分心（手动按钮 + 自动检测上报）。
- `POST /api/distractions`：独立分心记录（如刷手机开始/结束）。
- `GET /api/stats/daily`、`GET /api/stats/weekly`：统计。
- `GET /api/stats/insights`：洞察（按小时聚合分心，输出"几点最容易破功"）。
- `GET /api/settings`、`PUT /api/settings`：设置。
- `POST /api/monitor/heartbeat`：检测助手上报（可选）。

### 5.5 桌面检测助手

- run.py 启动 uvicorn + 独立线程/进程，每 2-5 秒轮询 `GetForegroundWindow`。
- 取前台窗口的进程名 + 窗口标题，与黑名单匹配。
- 命中黑名单且当前存在 running session → 自动记一条分心。
- 助手未运行 → 自动检测降级，手动分心仍可用。

## 6. 边界与错误处理

- **计时精度**：浏览器切后台时用时间戳差值计算，不依赖 setInterval 精确性。
- **离线**：PWA 离线时计时功能保持可用，数据暂存 localStorage 队列，联网后自动补交。
- **手机离线补交**：实现为简单 pending queue（几十行），不做复杂同步。
- **时间基准**：正常在线以服务器时间为准；离线补交的记录携带客户端时间戳，服务端接受（本地单用户可信）。
- **误判**：电脑端只判"在岗/无操作"，不把页面切换当分心；黑名单命中必须伴随"当前有进行中的会话"才自动记录，避免误报。
- **安全**：局域网服务无鉴权，仅限可信网络使用；README 提示防火墙放行方式、数据位置与备份方法（直接复制 data/focus.db 即可）。

## 7. MVP 范围（周末版）

**做**：
1. 专注会话：启动仪式、计时、完成/放弃、分心按钮、质量自评（10 秒）。
2. 电脑端自动检测抖音（客户端 + 网页窗口标题）+ 在岗检测（活动监听，超时回页面补问）。
3. 手机端 PWA：拿起归因、可安装桌面、离线暂存。
4. 日/周统计 + 连续达标天数 + 下周时长建议。
5. 设置页：黑名单、目标时长、深度时段。
6. 一键启动脚本 + README。
7. 接口自动化测试（pytest）+ 手动冒烟清单。

**不做**（防止范围蔓延）：
- 原生安卓拦截、浏览器扩展、云端同步、多用户、AI 教练、跨端实时搭档模式、完整成就体系、Web Push 推送、多设备会话合并（MVP 各端独立会话）。
- 后置（v2 再做）：恢复力仪式/裸专注日/月度体检/脚手架递减的自动编排。

**设计依据**：不归零机制（对抗破罐破摔）、质量自评（对抗"坐满≠专注"）、自适应渐进（对抗强度恒定）、成长报告替代金币（对抗奖励饱和）、恢复力训练与脚手架递减（对抗外部归因）、毕业机制（对抗工具依赖）。详见 3.5。

## 8. 成功标准

- **自用验证**：连续用 2 周，专注会话完成率 > 60%，周手机占用时长趋势下降。
- **技术验证**：电脑端开抖音能自动记录；手机端 PWA 安装可用；数据不丢（离线补交正常）。
- **验收路径**：`python run.py` → 电脑浏览器打开 → 手机同一局域网访问并安装 PWA。

## 9. 后续路线（预留，不进 MVP）

1. **原生安卓版**：使用情况访问（UsageStats）+ 无障碍服务，识别抖音等 App 包名，可弹拦截页。
2. **浏览器扩展**：标签级识别 douyin.com 等，拦截/提醒更精准。
3. **跨端搭档模式**：电脑开始专注时手机进入"搭档模式"，拿起即记录。
4. **云端同步 + Web Push**：手机不在同一局域网时也能收提醒、同步数据。
5. **AI 教练**：基于数据做个性化复盘与建议（服务端预留扩展点）。
