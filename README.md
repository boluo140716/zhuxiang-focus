# 一炷香 专注训练营

点一炷香，专注一炷香。不是约束工具，而是「觉察 → 训练 → 习惯」的专注力训练产品。目标是让你**毕业**——连续达标后，脱离产品也能专注。

设计文档：`docs/superpowers/specs/2026-08-03-focus-training-design.md`
实现计划：`docs/superpowers/plans/2026-08-03-focus-training-plan.md`

## 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 启动

```bash
python run.py
```

- 电脑端浏览器打开 `http://127.0.0.1:8000`
- 服务监听 `0.0.0.0:8000`，同时会启动桌面监控助手（Windows 前台窗口轮询）

### 3. 手机端（安卓）

1. 手机和电脑连**同一个 WiFi**
2. 查看电脑局域网 IP（`ipconfig` 里 WLAN 的 IPv4 地址，如 `192.168.1.2`）
3. 手机浏览器打开 `http://<电脑IP>:8000`
4. 浏览器菜单 →「安装应用 / 添加到主屏幕」→ 桌面出现「一炷香」图标
5. 如无法访问，需在 Windows 防火墙放行 8000 端口（见下方）

### Windows 防火墙放行（手机访问失败时）

```powershell
New-NetFirewallRule -DisplayName "Yizhuxiang 8000" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000
```

## 怎么用

- **专注页**：写下本次目标 → 开始 → 计时开始。中途分心点「破功了」；做完点「完成」→ 10 秒质量自评。
- **手机端**：专注时把手机放下；中途拿起会被感知，回来 3 秒归因（默认记「刷手机」，可改）。
- **电脑端**：正常干活不算分心；超过 3 分钟没操作，回到页面时会问一句。**抖音**（客户端+网页）在前台会被自动记录。
- **统计页**：今日/本周数据、连续达标天数、下周建议时长、几点最容易破功。
- **设置页**：分心黑名单（每行一个关键词）、目标时长、深度时段提醒。

### 达标规则

- 达标日 = 当天有会话实际时长 ≥ 目标×80% **且** 完成度自评 ≥ 60
- 连续天数只降级不归零（当天有「回弹任务」入口，5 分钟也算恢复）
- 下周建议：完成率 > 80% 加 5 分钟，< 50% 减 5 分钟（上限 60，下限 5）

## 离线与数据

- PWA 离线时计时照常，所有操作暂存在浏览器本地，联网后自动补交
- 数据文件：`data/focus.db`（SQLite），备份 = 复制这个文件
- 服务是**单用户、无鉴权**的局域网服务，请只在可信网络使用

## 冒烟清单（首次使用建议按此验证）

1. 电脑端开始一场专注 → 打开抖音客户端 → 2-5 秒内统计页出现 1 条自动分心记录
2. 手机安装 PWA → 开始专注 → 切去刷 1 分钟 → 回来弹归因 → 选「刷手机」→ 数据落库
3. 断网操作（开始/结束一场专注）→ 恢复联网 → 20 秒内自动补交，统计页数据不丢
4. 关掉服务重启 → 数据仍在（`data/focus.db` 持久化）
5. 设置页把黑名单改成 `bilibili` → 打开 B 站 → 自动记录

## 技术架构

- 后端：FastAPI + SQLModel + SQLite（`app/`）
- 前端：单页原生 JS + PWA（`static/`）
- 桌面监控：ctypes 调 Windows API 轮询前台窗口（`app/monitor/`）
- 测试：`python -m pytest -q`（30 个用例，覆盖 API、算法、黑名单、监控逻辑）
- 前端冒烟：`node tests/frontend_smoke.cjs`（jsdom，28 项：首页/遗留会话自动结束/弹窗逃生/会话流程）
- 浏览器端到端：`node tests/e2e_smoke.cjs`（无头 Chrome/Edge + 独立测试库，29 项：SW 缓存/视觉显隐/完整流程）
- 前端测试依赖：项目根目录执行 `npm install`（jsdom）；E2E 需本机装有 Chrome 或 Edge，可用环境变量 `CHROME_PATH` 指定浏览器路径

## 页面卡在旧版本？（缓存问题）

- 症状：页面一直显示旧内容、弹窗不消失、刷新无效
- 解决：**一次**打开 `http://127.0.0.1:8000/?v=6`（带版本号的地址会绕过旧缓存并自动更新），之后正常访问 `http://127.0.0.1:8000` 即可
- 原理：早期版本 Service Worker 缓存优先，会把旧页面直接发给浏览器；当前版本为网络优先、新 Service Worker 接管时自动刷新，上述地址用于一次性绕过旧缓存完成更新

## 已知限制

- 手机端 PWA 无法识别具体 App（系统权限限制），只能感知「拿起」并归因
- 电脑端「无操作提醒」在浏览器切后台时不可见，降级为回到页面时补问
- 深度时段提醒为打开页面时的横幅提示，非系统推送
